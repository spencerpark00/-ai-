# MRO Copilot은 어떻게 만들어졌나 — 서비스 제작 여정

> 이 문서는 **비전공 팀원도 읽고 이해할 수 있게** 쓴 제작 기록입니다.
> 어려운 용어는 풀어 쓰고, "무엇을 왜 어떻게 했는지"를 순서대로 이야기합니다.
> 실제 서비스: **https://mro-copilot.onrender.com**

---

## 0. 한 문장으로

정비 지식을 **컴퓨터가 따라갈 수 있는 형태(지식그래프)로 정리**하고,
그 위에 **정비사가 쓰는 현장 앱**과 **관리자가 보는 관제 콘솔**을 얹은 뒤,
정비사가 일하면 그 결과가 **다시 지식그래프에 쌓이는 순환**까지 만든 서비스.

---

## 1. 우리가 풀려는 문제

정비 현장에는 정보가 여기저기 흩어져 있습니다. 매뉴얼 따로, 과거 사례 따로, 선배 머릿속 따로.
정비사가 "이 부품 이거 어떻게 하지?" 물어보면, 그걸 한 번에 답해주는 게 없습니다.

그래서 우리는 **흩어진 정비 지식을 하나로 연결**하고, 정비사가 물어보면 답해주는 서비스를 만들기로 했습니다.
단, AI가 멋대로 판정하는 게 아니라 **최종 판단은 항상 정비사**가 하도록 (이게 우리 프로젝트의 원칙입니다).

---

## 2. 만드는 순서 (큰 그림)

```
① 지식 정리    →  ② 지식그래프    →  ③ 정비사 현장 앱   →  ④ 관리자 관제 콘솔
(무엇을 연결?)     (컴퓨터가 읽게)     (현장에서 일하게)      (전체를 관리하게)
                                          ↘                    ↙
                              ⑤ 실시간 연동 + 환류(순환)
                              (일한 결과가 다시 지식이 된다)
                                          ↓
                              ⑥ 인터넷에 올리기 (누구나 쓰게)
```

처음엔 ①~④까지 만들었고, 최근에 **⑤ 대화형 AI·관리자 콘솔·순환 구조**를 붙여 크게 발전시켰습니다.

---

## 3. ① 지식 정리 — "무엇을 어떻게 연결할까" (온톨로지)

**"온톨로지"** 는 쉽게 말하면 **"정비 지식을 단어가 아니라 관계로 적어둔 것"** 입니다.

- 보통 매뉴얼: "유압펌프는 유압계통에 속한다" (사람이 읽는 문장)
- 온톨로지: `[유압펌프] → 속한다 → [유압계통]` (컴퓨터가 따라갈 수 있는 연결)

정비사 질문은 두 종류인데, 두 번째가 우리 서비스의 핵심이라 검색이 아니라 지식그래프가 필요했습니다.
- **"이거 절차가 뭐야?"** → 매뉴얼 검색으로 답할 수 있음
- **"다음에 뭐 해야 돼? / 얘 원래 이래?"** → 연결을 따라가야 답이 나옴

### 무슨 데이터를 썼나요? (전부 공개된 진짜 데이터)

| 데이터 | 무엇 | 규모 |
| --- | --- | --- |
| **FAA JASC 코드표** | 미국 항공청 항공기 계통 분류 | 547개 코드 |
| **FAA SDR** | 실제 정비 결함 보고서 | 31,582건 |
| **FAA 정비 핸드북** | 검사 절차·공구·주의사항 | 공식 교재 |
| **현장용어 사전** | 정비사 VOC (메가네→링 렌치 등) | 56개 |

> 핵심: 분류를 **우리가 지어낸 게 아니라 FAA 표준을 그대로 가져왔다.** "임의로 만든 거 아니냐"에 "표준입니다"로 답할 수 있습니다.

---

## 4. ② 지식그래프 만들기 — "컴퓨터가 읽게" (Neo4j)

**Neo4j** 는 "연결(그래프)"을 저장하는 데이터베이스입니다. 표가 아니라 **동그라미(개체)와 선(관계)** 으로 저장해서, "이거랑 이거가 어떻게 연결됐나"를 따라가기에 딱 맞습니다.

공개 데이터를 가공해 적재한 결과: **동그라미 약 1,300개 + 선 약 2,500개**
- 계통 598개 · 부품 141개 · 결함 81종 · 실제 사례 500건 · 정비 절차·공구·주의사항

넣고 끝이 아니라 "모든 부품이 계통에 연결됐나?" 같은 **검사를 통과**해야 "제대로 섰다"고 합니다.

---

## 5. ③ 정비사 현장 앱 — "현장에서 일하게" (index.html)

정비사가 태블릿/폰으로 쓰는 **현장용 앱**입니다. 처음엔 "검색 화면"이었는데, 지금은 **실제 작업 흐름**을 담게 발전했습니다.

### 오늘의 작업 → 5단계 처리

첫 화면에 **오늘 배정된 작업 목록**이 뜨고, 하나를 골라 5단계로 처리합니다:

```
① 작업 받기 → ② 로봇/직접 촬영 → ③ AI 결과 → ④ 정비사 판정 → ⑤ 자동 기록
```

- **위험도 먼저** 보여줍니다 (🔴즉시조치 / 🟠정비필요 / 🟢경미) — 정비사가 5초 안에 판단
- 근거(과거 사례·검사 절차·공구)는 **눌렀을 때만** 깊이 보기 (화면을 안 어지럽게)
- **최종 판정은 정비사** (정상/재검사/수리) — AI는 "이상 후보"까지만
- 판정하면 결과가 **자동 기록 + 관리자에게 전달**됩니다

### 하단 대화형 AI 챗봇 — "물어보면 답해주는 도우미" (§5-1)

작업 중 궁금한 걸 **말이나 글로 물어보면** 답해줍니다. 이게 크게 진화한 부분입니다 → 다음 장.

> 오케스트레이션(작업 흐름 통제)과 로봇 검사 HUD도 만들어 뒀고(`orchestration.html`·`robot.html`), 제안서 별첨/시연용으로 유지합니다.

## 5-1. 대화형 AI 챗봇 — 규칙에서 진짜 AI로

챗봇은 두 단계로 발전했습니다.

**처음 (규칙 기반):** 정해진 키워드에 정해진 답을 붙이는 방식. "정해진 목록을 이어붙이는 느낌"이라 AI 같지 않았습니다.

**지금 (LLM + 지식그래프):**
- **LLM(생성형 AI)** 을 얹었습니다 — 무료인 **Google Gemini** 사용 (환경변수만 바꾸면 Claude 등으로 교체 가능)
- **RAG** — LLM이 아무 말이나 못 하게, **우리 지식그래프(Neo4j)에서 근거를 찾아** 그 안에서만 답하게 함 (환각 억제). 근거에 없으면 "제 자료엔 없어요"라고 솔직하게
- **현장용어 이해** — "메가네", "야마" 같은 현장말도 알아듣고 표준어(링 렌치, 나사산 손상)로 답함
- **대화 기억** — "그럼 그건?" 같은 연계 질문도 앞 맥락을 이어받아 답함

→ 이제 정해진 답이 아니라 **옆에서 같이 일하는 선배처럼** 자연스럽게 답합니다.

> 설계 포인트: `의도 파악 → 지식 조회 → 답변 생성` 3단 구조로 만들어서, LLM은 ①③만 교체하고 **지식 조회(Neo4j)는 그대로** — "안 갈아엎고 얹기".

## 6. ④ 관리자 관제 콘솔 — "전체를 관리하게" (manager.html)

정비사 앱이 "현장에서 일하는 화면"이라면, 관리자 콘솔은 **"도입 결과 운영이 개선되고 있는지 판단하는 화면"** 입니다. 사내 시스템 느낌의 **관제 콘솔(MRO OPS CENTER)** — 로그인 후 5개 메뉴.

| 메뉴 | 무엇을 보나 |
| --- | --- |
| **운영** | 오늘 카운터 · **가동 보드(정비사·로봇 5쌍)** · 승인 대기큐 · 검사 로봇 현황 · AI 운영 제안 · 활동 이력 |
| **품질** | 재검사·재촬영 · 반려 사유 · 결함 발견 Top · 지식 자산 규모 |
| **인재** | 숙련도별 부하 · 신입 지원 · 팀 비교 (개인 지목 없음) |
| **지식** | **케이스 브라우저** — 환류된 검증사례 + 외부사례를 실물로 열람 (§7) |
| **효과 리포트** | 리드타임·재작업률·검증사례 축적 (전→후→목표) · 심의·시연 전용 |

### 관리자 콘솔의 원칙 (팀 설계품질정의서 반영)
- **기술 용어 ZERO** — 온톨로지·RAG·Edge 같은 말은 화면에 없음 (뒤에서 조용히 작동)
- **판단 중심, 문제 우선** — 평상시엔 조용히, 긴급·지연·오류만 색·알림으로
- **금액·ROI는 화면에 없음** — 재무는 기대효과 문서의 몫 (운영 화면과 분리)
- **AI는 제안까지, 실행은 관리자** — 자동 배정·실행 버튼 없음

### 두 화면, 하나의 서비스
정비사 앱(현장·모바일·다크)과 관리자 콘솔(사무실·데스크톱·라이트)은 **일부러 다르게** 생겼습니다 — 쓰는 사람과 기기가 다르니까요. 대신 **이름·색(대한항공 네이비)·용어**로 하나의 제품처럼 묶었습니다.

## 7. ⑤ 실시간 연동 + 환류 — "일한 결과가 다시 지식이 된다"

이번 발전의 핵심입니다. 정비사와 관리자 화면은 **직접 연결돼 있지 않고**, 데이터가 서버를 통해 흐릅니다.

### 실시간 연동
정비사가 작업을 **판정**하면 → 서버에 반영 → **관리자 콘솔이 4초 안에 자동 갱신**됩니다.
- 완료 +1, 승인 대기큐에 적재, 활동 이력에 기록
- 정비사에겐 "관리자 현황으로 전달됐습니다" 팝업만 (정비사는 관리 화면을 열 필요 없음)

### 환류 (write-back) — 순환 완성
정비사가 **승인**한 작업은 → **Neo4j 지식그래프에 검증사례로 축적**됩니다.

```
        ┌──────── 읽기 (근거·KPI) ────────┐
        ▼                                  │
[정비사 앱] ─승인(정비사만)→ [서버] ─쓰기→ [Neo4j 지식그래프]
   현장                        │           검증사례 축적 ↑
        └─작업 결과 전달──→ [관리자 콘솔] ──┘
                          (실시간 현황 + 지식 KPI)
```

- 예전엔 지식그래프에서 **읽기만** 했는데, 이제 **쓰기(축적)까지** 붙어 순환이 완성됐습니다
- 정비사가 일할수록 관리자 지식 탭의 **검증(환류) 사례 수가 실제로 늘어납니다**
- 승인된 것만 쌓입니다 (**HITL** — 사람이 확인·승인한 지식만 등록)

→ 우리 프로젝트가 처음부터 말한 **"작업할수록 대한항공만의 지식이 쌓인다"** 가 말이 아니라 **코드로 구현**됐습니다.

## 8. ⑥ 인터넷에 올리기 — "누구나 쓰게" (클라우드 배포)

처음엔 내 컴퓨터에서만 돌아가서 팀원한테 못 보여줬습니다. 그래서 클라우드에 올렸습니다.

```
사용자 브라우저  →  Render(화면·서버)  →  Neo4j Aura(지식그래프)  +  Gemini(대화형 AI)
                    둘 다 인터넷에 있음 → 내 컴퓨터 꺼도 됨
```

| 부분 | 올린 곳 | 무료? |
| --- | --- | --- |
| 지식그래프(데이터) | **Neo4j Aura** | 무료 |
| 화면·서버 | **Render** | 무료 |
| 대화형 AI | **Google Gemini** | 무료 등급 |
| 코드 보관 | **GitHub** | 무료 |

**https://mro-copilot.onrender.com** — 링크 하나면 누구나 열 수 있습니다. 코드를 GitHub에 올리면(push) Render가 자동으로 다시 배포합니다. (비밀번호·API 키는 코드가 아니라 **환경변수**로만 넣어 안전하게 관리)

> ⚠️ 무료 서버라 15분 방치되면 잠들었다가, 다시 열면 첫 화면이 **최대 50초** 걸립니다. 발표 직전에 미리 깨워두면 됩니다.

## 9. 전체 여정 한눈에

```
[정비 지식이 흩어져 있다]
   ↓ ① 온톨로지 — 지식을 "관계"로 정리 (FAA 공개 데이터)
[연결 구조 설계]
   ↓ ② Neo4j — 지식그래프로 적재 (노드 1,300+ / 관계 2,500+)
[동그라미·선으로 저장된 지식]
   ↓ ③ 정비사 현장 앱 — 오늘의 작업 5단계 + 대화형 AI(Gemini+RAG+현장용어+대화기억)
   ↓ ④ 관리자 관제 콘솔 — 운영·품질·인재·지식·효과 리포트 (로그인·기술용어 zero)
   ↓ ⑤ 실시간 연동 + 환류 — 정비사 판정 → 관리자 반영 → 지식그래프 축적 (순환 완성)
   ↓ ⑥ 클라우드 배포 — 누구나 링크로 (Aura + Render + Gemini)
[https://mro-copilot.onrender.com]
```

## 10. 핵심 3가지 (기억할 것)

1. **지어낸 데이터가 아니다** — FAA 공개 표준(JASC 547코드)과 실제 정비 보고 31,582건에서 나왔다.
2. **AI는 판정하지 않는다** — 구조 자체가 그렇게 되어 있다. AI는 "후보/제안"까지, 확정은 정비사만.
3. **작업 결과가 지식이 된다** — 정비사가 승인하면 Neo4j에 검증사례로 **실제 축적**된다 (환류·HITL). 말이 아니라 코드로 구현됨.
