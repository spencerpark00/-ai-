# 관리자 대시보드 설계 정리본

> **한 줄 목적:** 관리자 대시보드는 *"우리 서비스를 도입하면 MRO 운영이 실제로 좋아진다"* 는 **기대효과가 눈에 보이는 숫자로 관찰되는 화면**이다.
>
> **한 줄 가치:** "전체 현황은 한눈에, 문제는 즉시 대응."

이 문서는 코치 피드백 + 팀 조사 + 논의 내용을 합쳐, 관리자 대시보드를 **무엇을 · 어떻게 · 어떤 데이터로** 만들지 정리한 설계 기준이다.

---

## 1. 왜 관리자 대시보드인가 (코치 피드백)

- 정비사 앱만으로는 **제품 전체를 설명할 수 없다.** 관리자 대시보드까지 있어야 서비스 전체 형상이 보인다.
- **"기대효과가 대시보드에 녹아 있어야 한다"** = 기대효과 *문구*를 적으라는 게 아니라, **우리가 주장하는 가치가 실제 운영지표로 관찰**되어야 한다는 뜻.
- 정비사 화면이 *작업을 수행하는 곳*이라면, 관리자 대시보드는 **도입 결과 운영이 개선되고 있는지 판단하는 곳**이다.

---

## 2. 설계 원칙 (4가지)

| 원칙 | 의미 |
|---|---|
| **① 기대효과 = 관찰되는 숫자** | 가치를 말로 쓰지 말고 정량 지표로 보여준다 |
| **② 판단 중심 · 단계적** | 평소엔 숫자만, 문제 있을 때만 눌러서 사진·이력 깊이 보기 (나열 금지) |
| **③ 기술 용어 ZERO** | 온톨로지·RAG·Edge·오케스트레이션은 화면에 없음. 뒤에서 조용히 작동 |
| **④ 효과는 델타(변화)로** | 값 하나("95%")가 아니라 **전 → 후 → 목표**로 보여야 개선이 보인다 |

---

## 3. 화면 구조 — 무엇을 중점으로 보이나

관리자가 5초 안에 "효과 있네 / 문제 여기네"를 파악하도록 **2단 + 추이**로 구성한다.

### 🔺 HERO 밴드 (제일 크게) = 기대효과 4대 증거

| 중점 키워드 | 핵심 수치 | 근거 |
|---|---|---|
| **작업 효율** | 평균 리드타임 **↓ 10~20%** | 정보 탐색·이동·기록 시간 단축 |
| **정비 품질** | 품질 완전성 / 증빙 완결률 **95%↑** | Work Card·사진·검사 자동 연결 |
| **경제 효과** | 회수 **1,040h/년 → 3,100~4,000만원**(검증 목표) · 투자회수 **2~4년** | 0.5 FTE 절감 가정 |
| **역량 향상** | 신입–숙련 작업 격차 **↓** (신입도 숙련자 수준으로) | 서비스 안내·사례 지원 효과 |

> 각 지표는 **전 → 현재 → 목표 → 달성** 형태로 표시 (4번 원칙).

### 🔻 운영 밴드 (그 아래) = 오늘 현황 · 판단

```
[오늘 작업]  [완료]  [진행]  [🔴 긴급]  [⚠ 지연]      ← 숫자 카드
[결함 발생]  [재검사]  [로봇 활용률]  [SLA 초과]

병목 현황                      결함 Top3
 검사 대기 ▇▇▇                 부식 ▇▇▇
 승인 대기 ▇▇                  흠집 ▇▇▇▇
 부품 대기 ▇                   균열 ▇

⚠ 지연·위험 알림  [자세히 ▸]   ← 문제만 콕, 눌러야 사진·이력
```

### 📈 추이 밴드 (선택) = MRO 품질 변화 시각화

- 주/월 단위 **리드타임 · 품질 완전성 · 재작업률** 추세선 → "시간이 갈수록 좋아진다"를 시각화

### 용어 풀이 (비전공자용)

- **긴급 작업** — 지금 당장 처리해야 하는 위험 작업 (제일 먼저 봄)
- **SLA 초과** — 정해진 시간 안에 못 끝낸 작업 ("늦어지는 일")
- **병목** — 작업이 어디서 막혀 밀리는지 (검사 대기? 승인 대기? 부품?)
- **로봇 활용률** — 전체 작업 중 로봇이 얼마나 도왔는지

## 4. 정량 기대효과 — 어떤 숫자를, 어떤 컬럼으로

### 4-1. 컬럼 스키마 (핵심)

정량 수치는 값 하나로 두지 않고, **전 → 후 → 목표 → 달성**으로 보여준다.

| 지표 | 도입 전 | 현재(PoC) | 목표 | 달성 |
|---|---|---|---|---|
| 정보 검색시간 | 12분 | 6분 | 50%↓ | ✅ |
| Work Card 완결률 | 72% | 91% | 95%↑ | 🔶 |

*(위 숫자는 컬럼 구조 설명용 예시)*

### 4-2. 두 대 가치 축

기대효과는 두 축으로 압축한다 (코치의 5개 카테고리를 정리한 형태).

| 작업 효율 — *리드타임* | 지식 내재화 — *품질 완전성* |
|---|---|
| 전체 리드타임 10~20%↓ | 품질 완전성 95%↑ |
| 정보 검색시간 50%↓ | Work Card 완결률 95%↑ |
| 공구·이동시간 30%↓ | 작업 증빙률 90%↑ |
| 기록시간 50%↓ | 검사 누락률 5%↓ |
| 대기시간 20%↓ | 재작업률 10~20%↓ |
| 로봇 작업 성공률 95%↑ | 유사사례 검색 50%↓ |
| 음성 인식 성공률 90%↑ | 지식 재사용률 30%↑ |

### 4-3. 경제 효과 (ROI) 계산 근거

| 항목 | 값 |
|---|---|
| 1 FTE 연간 근로시간 | 2,080시간 |
| 0.5 FTE 절감시간 | **1,040시간/년** (월 87h · 일 4h) |
| 대한항공 2025 직원 평균급여 | 연 1억 2,300만원 (시간당 ≈ 5.9만원) |
| 총 생산성 가치 | **약 6,150만원/년** |
| 직접 비용절감 (전환율 50~65%) | **약 3,100~4,000만원/년** |
| 투자회수 (초기투자 1억 가정) | **약 2.5~3.2년** |

**도입 대수별 확산**

| 로봇 수 | 인력 환산 | 연 절감시간 | 직접 절감액 |
|---|---|---|---|
| 1대 | 0.5 FTE | 1,040h | 0.31~0.40억 |
| 5대 | 2.5 FTE | 5,200h | 1.54~2.00억 |
| 10대 | 5 FTE | 10,400h | 3.08~4.00억 |

> ⚠️ **중복 합산 금지:** `0.5 FTE ↔ 팀 생산성 8~13% ↔ 추가 처리 150~260건`은 **같은 시간절감을 다르게 표현**한 것. 금액에 더하면 안 됨. 대시보드에선 "같은 절감을 3가지 관점으로" 토글로 보여주고, ROI 금액은 **한 번만** 계산.

## 5. "지금 데이터가 없는데 기대효과를 보여줄 수 있나?" — 정직한 접근

정비사 앱도 아직 PoC 흐름만 도는 프로토타입이라, 실제 성과 데이터가 쌓여 있지 않다. **그래도 만들 수 있고, 그게 PoC 대시보드의 정석이다.**

### 5-1. PoC 대시보드는 "달성한 성과"가 아니다

지금 단계 대시보드가 보여줄 것은:

> **"무엇을 · 어떻게 측정할지(측정 설계) + 목표치 + 지금까지의 시연 실측"**

"이미 이만큼 달성했다"가 아니다. 심사에서도 **"측정 체계가 있고 목표가 명확하다"**를 더 높이 본다. (확정 성과라 우기면 오히려 감점)

### 5-2. 지금 채울 수 있는 3개 데이터 층

| 층 | 예 | 상태 |
|---|---|---|
| **① 실데이터 (Neo4j)** | 결함 Top3, 과거 사례 수, 작업 구성 | 진짜 숫자 (있음) |
| **② PoC 시연 실측** | 이번 데모 작업의 촬영 성공·단계 시간 | 진짜지만 N=1 |
| **③ 목표 + 시뮬** | 리드타임↓20%, ROI, 숙련도 향상 | **"PoC 검증 목표" 라벨 필수** |

→ 각 숫자에 **"실측 / 시연 / 검증 목표"** 라벨을 정직하게 붙인다.

### 5-3. 오히려 강한 한 수 — "어디서 측정되는지"를 보여주기

각 지표 옆에 **그 숫자가 어디서 자동 수집되는지**를 표시한다:

| 지표 | 측정 출처 |
|---|---|
| 리드타임 | 작업 단계별 타임스탬프 |
| 증빙 완결률 | Work Card 자동 기록 |
| 촬영 성공률 | 로봇 촬영 로그 |
| 재작업률 | 정비사 판정·반려 기록 |

→ **"지금은 시연값이지만, 배포되면 이 데이터가 자동으로 쌓여 진짜 측정된다"**를 증명. 우리 서비스의 **환류(자동 축적)** 설계와 맞물린다.

### 5-4. 데이터를 채우는 방식 (채택: 시연 시드 데이터)

| 방식 | 설명 | 평가 |
|---|---|---|
| **① 시연 시드 데이터** ✅ | 작업 기록 10~20건을 심고 대시보드가 **실제 집계** | 추천 — "살아있는" 느낌, 앱과 연동 시연 가능 |
| ② 목표 + 라벨만 | 현재값은 "측정 예정" 표기 | 제일 정직하나 화면이 비어 보임 |
| ③ 예시값 박제 | 화면 구성용 숫자 하드코딩 | 빠르지만 "박제된" 느낌 |

**① 시연 시드 데이터** 채택 이유:
- 대시보드가 실제로 "기록 → 집계 → 지표" 파이프라인으로 작동
- 정비사 앱에서 작업 하나 완료하면 **대시보드 숫자가 실제로 +1** 되는 것도 시연 가능
- 여전히 정직 — **"PoC 시연 데이터"** 라벨 유지

## 6. 정비사 vs 관리자 (역할 구분)

| 구분 | 정비사 🧑‍🔧 | 관리자 👔 |
|---|---|---|
| **역할** | 현장에서 직접 검사·수리 | 전체 작업 관리 |
| **화면** | 작업 흐름 5단계 + 대화 | 대시보드 (숫자·차트) |
| **먼저 보는 것** | 🔴 위험도 → 결함 → 위치 → 조치 → 시간 | 완료/진행/긴급/지연 → 병목 → 결함 Top3 |
| **근거는?** | 눌렀을 때만 (왜 위험한지·과거 사례) | 문제 있을 때만 (사진·이력) |
| **한 줄 가치** | 찾고·촬영하고·기록하는 시간을 줄여 정비에 집중 | 전체 현황은 한눈에, 문제는 즉시 대응 |

## 7. 기술 용어 ZERO 원칙

화면에는 우리가 뒤에서 쓰는 기술 이름을 **절대** 노출하지 않는다.

| ❌ 기술 용어 | ✅ 사용자 언어 |
|---|---|
| 온톨로지 기반 데이터 통합 | 과거 비슷한 사례 |
| 지식그래프 조회 | 이 부품 이력 보기 |
| RAG 검색 | 매뉴얼에서 찾기 |
| Edge AI / 클라우드 추론 | (아예 안 보임 — 뒤에서 처리) |
| AI 오케스트레이션 | (아예 안 보임) |
| AI 챗봇 | 작업 도우미 |

> **자문:** "이건 사용자가 바로 보고 싶은 결과인가? 아니면 뒤로 숨겨야 할 과정인가?"

## 부록 A. KPI 산출식

```
리드타임 단축률(%) = (도입 전 리드타임 − 도입 후 리드타임) ÷ 도입 전 리드타임 × 100
정비 품질 완전성(%) = 누락 없이 완료된 필수 항목 수 ÷ 전체 필수 항목 수 × 100
Work Card 완결률(%) = 필수항목 모두 작성된 Work Card 수 ÷ 전체 완료 Work Card 수 × 100
작업 증빙률(%)      = 필수 사진·영상 확보 작업 수 ÷ 증빙 필요 전체 작업 수 × 100
지식 재사용률(%)    = 기존 사례·매뉴얼 활용 작업 수 ÷ 유사사례 활용 가능 작업 수 × 100
연간 지식 축적량    = 일평균 지원 작업 수 × 연간 운영일수 × 자동 기록률
```

## 부록 B. 출처 및 전제

- **코치 피드백** (2026-07-28) — "기술 말고 사용자가 얻는 결과를 보여줘라", 정비사·관리자 화면 분리, 기대효과=관찰지표
- **정량 기대효과 조사** — 0.5 FTE 가정, 대한항공 2025 사업보고서 평균급여, 근로기준법 2,080h 기준
- **참조 baseline** — 대한항공 공개 사례: 외관검사 8~10시간 → 약 50분 (드론·로버 + AI 판독)
- ⚠️ 본 문서의 모든 수치(52건·↓20% 등)는 **화면·설계 설명용 예시/목표치**이며, 실제 성과는 **PoC 실측으로 확정**한다. 특히 금액·시간 지표는 **검증 목표치**로 표기한다.
