## A. AI가 "살아있게" — 판단 근거 Drawer

### 배경 (문제)
기존 "AI 운영 제안"은 카드에 `[참고함][무시]` 버튼만 있어, 심사위원이 **"그래서 AI가 뭘 했는데?"** 하고 물으면 답이 없었다. AI가 추천만 하고 끝나는 "정적"인 느낌.

### 무엇을 / 어떻게
- AI 제안 카드를 **클릭하면 우측 Drawer**가 열리고 *왜 이 추천인지* 근거를 실데이터로 펼침
- 제안이 상황에 따라 **2~3개 동적 생성** (판정 승인 병목 / 검사 대기 배분 / 재검사 주의)
- Drawer 내용: **판단 근거 표** + **연결 근거(Neo4j)** + **신뢰도(Confidence) 바**
- **정직 라벨** — 실측(라이브 집계) / Neo4j(그래프 조회) / 추정(휴리스틱)을 배지로 구분
- **HITL 유지** — 버튼은 관리자 판단 기록만, "자동 실행 없음" 명시
- 관리자가 누른 판단(참고함/무시/우선처리)은 **활동 이력에 실제로 기록**됨 (🤖 표시)

### 결과
"AI가 제안 → 관리자가 판단 → 그 판단이 이력으로 남는" **HITL 상호작용이 화면에 보임.**
서비스 이름이 *Copilot*인 이유가 화면에 드러나기 시작.

## B. 정비사별 실제 작업 → 관리자 보드 실시간 일치

### 배경 (문제)
- 로그인이 "역할(정비사)"까지만 있고 "누구인지"가 없었음
- 작업이 전원 공용, 가동보드 5쌍이 하드코딩(가짜) → 실제 활동과 무관
- (1차 시도) 콜드 진입 생동감을 위해 **가짜 자동진행(앰비언트)** 을 넣었더니, 정비사가 작업을 다 끝내도 관리자 보드는 계속 "작업중"으로 떠 **정비사 화면과 어긋남** → 신뢰도 저하

### 무엇을 / 어떻게
- **정비사 5명 계정** — 로그인에서 "누구"인지 선택 (박재현·이수민·최동욱·김하늘·한지원, 각자 로봇 MR-01~05)
- **정비사별 작업 배정**(1인 8건) — 로그인하면 자기 작업만 봄
- **단계 진행 실시간 보고** — 정비사 앱이 단계(작업받기→촬영→AI결과→판정→기록) 넘길 때마다 서버 보고
- 가동보드를 **실제 상태만** 반영하도록 재설계(가짜 진행 완전 제거):
  - 진행 중이면 → 실시간 단계·경과·로봇상태
  - 아니면 → 실제 배정 상태("배정 대기 N건 · 완료 M건" / 다 끝나면 "완료·유휴")
- **근무 세션 유지** — 판정이 순식간이라 '작업중'이 잠깐만 보이던 문제 → 로그인~로그아웃 동안 '작업중' 유지(작업 사이엔 '다음 작업 준비'), 로그아웃/유휴 시 '대기' 복귀

### 결과 (검증)
박재현 작업 시 — 앱 대기 6→5, 관리자 보드도 "대기 6건→5건·완료 2건→3건"으로 **정확히 일치**.
작업 중엔 그 행만 실시간(작업중 1/5→2/5…), 끝나면 실제 카운트로 복귀.

## C. 시연 생동감 — 데모 자동재생 + 동시접속

### 배경 (문제)
실제 상태만 반영하니, **혼자 시연하면 1명만 움직이고 나머지 4명·로봇 현황이 정적**.

### 무엇을 / 어떻게
- **데모 자동재생 토글**(관리자 가동보드 우측 상단)
  - ON: 로그인 안 한 정비사들이 **자기 실제 배정 작업을 자동 진행·완료** → 보드가 꽉 참
  - **실제 작업을 처리하므로 화면 일치 유지** (환류는 미기록 = 검증 지식은 사람 승인만, HITL)
  - 실제 로그인해 작업 중인 정비사는 **건드리지 않음**
  - 정비사별 시작 단계 stagger + 작업 사이 충전 페이즈 → 로봇 현황이 **촬영/이동/대기/충전**으로 다양하게 변함
- **동시접속** 검증 — 서버 한 대가 공유 상태를 들고 있어(Render 무료=단일 인스턴스), 팀원이 각자 다른 정비사로 로그인하면 **동시에 작업 + 관리자 보드에 전부 실시간 반영**

### 결과
- 혼자: 자동재생 ON → 5쌍 + 로봇 현황이 살아 움직임
- 팀: 각자 로그인 → 진짜로 동시에 여러 명이 움직임 (가장 설득력 높음)
